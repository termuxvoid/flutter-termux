# Building Android apps on Termux

This guide covers the Android configuration needed to build Flutter apps natively on Termux. Flutter itself comes from the TermuxVoid Flutter package; the Android SDK, NDK, and CMake come from the TermuxVoid Android packages.

No environment variables need to be exported. Point Flutter at the SDK once with `flutter config`, then set the paths and versions in the project's Gradle files.

## 1. Install the Android packages

```bash
pkg install android-sdk android-ndk android-cmake
```

| Package | Current version | Installed path |
| --- | --- | --- |
| `android-sdk` | 37.0.0 | `$PREFIX/opt/android-sdk` |
| `android-ndk` | 30.0.16248370 | `$PREFIX/opt/android-ndk` |
| `android-cmake` | 4.1.2 | `$PREFIX/opt/android-cmake/4.1.2` |

`$PREFIX` is normally `/data/data/com.termux/files/usr`.

## 2. Configure the Flutter SDK path

```bash
flutter config --android-sdk "$PREFIX/opt/android-sdk"
flutter doctor -v
```

This writes the SDK path to Flutter's configuration. It is persistent, so it only needs to be done once.

Do not set `ANDROID_HOME`, `ANDROID_SDK_ROOT`, or `ANDROID_NDK_HOME`. Flutter and Gradle use the configured SDK plus the project's `local.properties`.

## 3. Create a project

### Option A: apkgen-cli (recommended)

The TermuxVoid `apkgen-cli` Flutter template already contains the required Termux-specific Gradle changes. `apkgen` runs `flutter config --android-sdk "$PREFIX/opt/android-sdk"` and uses the template's `local.properties`, `gradle.properties`, and `app/build.gradle.kts`; it does not export environment variables.

```bash
pkg install apkgen-cli
apkgen create myapp --flutter
cd myapp
apkgen build flutter
```

`apkgen build flutter` runs `flutter build apk --debug --split-per-abi` and writes the APKs under `build/app/outputs/`.

Template source: [termuxvoid/apkgen-cli Flutter Android template](https://github.com/termuxvoid/apkgen-cli/tree/main/templates/flutter/android)

### Option B: flutter create and manual edits

```bash
flutter create myapp
cd myapp
```

Then apply the changes in the next section.

## 4. Project configuration

These are the edits the apkgen template makes to a default Flutter project.

### `android/local.properties`

Flutter normally generates `sdk.dir` and `flutter.sdk`. Add `cmake.dir` and `ndk.dir`:

```properties
sdk.dir=/data/data/com.termux/files/usr/opt/android-sdk
flutter.sdk=/data/data/com.termux/files/usr/opt/flutter
cmake.dir=/data/data/com.termux/files/usr/opt/android-cmake/4.1.2
ndk.dir=/data/data/com.termux/files/usr/opt/android-ndk
```

`local.properties` is machine-specific and is ignored by Git. Do not use shell variables such as `$PREFIX` in this file; Gradle reads the values literally, so use absolute paths.

### `android/gradle.properties`

Keep the values generated by the current Flutter template, and add the TermuxVoid aapt2 override:

```properties
org.gradle.jvmargs=-Xmx8G -XX:MaxMetaspaceSize=4G -XX:ReservedCodeCacheSize=512m -XX:+HeapDumpOnOutOfMemoryError
android.useAndroidX=true
android.newDsl=false
android.builtInKotlin=false

# TermuxVoid custom android-sdk aapt2
android.aapt2FromMavenOverride=/data/data/com.termux/files/usr/opt/android-sdk/build-tools/37.0.0/aapt2
```

The aapt2 path must match the installed build-tools version.

### `android/app/build.gradle.kts`

Add `buildToolsVersion` and set `ndkVersion` to the installed TermuxVoid NDK:

```kotlin
android {
    namespace = "com.example.myapp"
    compileSdk = flutter.compileSdkVersion
    buildToolsVersion = "37.0.0"
    ndkVersion = "30.0.16248370"
    // ...
}
```

The default Flutter template uses `ndkVersion = flutter.ndkVersion`, which points at a different NDK revision. Replace it with the version provided by `android-ndk`.

Keep `compileSdk = flutter.compileSdkVersion` and the existing `compileOptions` and `kotlin` blocks.

### `android/settings.gradle.kts` and the Gradle wrapper

No Termux-specific changes are needed when the project is created with Flutter 3.47.8. The generated project already uses:

- Android Gradle Plugin `9.1.0`
- Kotlin `2.4.0`
- Gradle `9.3.1`

These match the apkgen Flutter template. If you are porting an older project, update these versions before building.

## 5. Build and run

With a device connected over ADB or wireless debugging:

```bash
flutter devices
flutter run -d <device-id>
```

Build a debug APK:

```bash
flutter build apk --debug --split-per-abi
```

The APKs are written to `build/app/outputs/flutter-apk/`.

To use apkgen instead:

```bash
apkgen build flutter
```

| Package | Version | Used in |
| --- | --- | --- |
| `android-sdk` | 37.0.0 | `sdk.dir`, `buildToolsVersion`, `android.aapt2FromMavenOverride` |
| `android-ndk` | 30.0.16248370 | `ndk.dir`, `ndkVersion` |

When TermuxVoid updates one of these packages, update the matching value in `local.properties`, `gradle.properties`, or `app/build.gradle.kts`.

## Troubleshooting

### `aapt2` not found or fails to run

Check that `android.aapt2FromMavenOverride` points to the `aapt2` binary in the installed build-tools directory:

```bash
ls -l "$PREFIX/opt/android-sdk/build-tools/37.0.0/aapt2"
```

Update the path if the build-tools version changed.

### NDK version mismatch

Gradle must find the exact NDK version named in `android/app/build.gradle.kts`. Check the installed version:

```bash
grep Pkg.Revision "$PREFIX/opt/android-ndk/source.properties"
```

Then make `ndkVersion` and `ndk.dir` match it.

### CMake not found

Verify `cmake.dir` points to the installed TermuxVoid CMake directory:

```bash
ls "$PREFIX/opt/android-cmake/4.1.2/bin/cmake"
```

### Gradle cannot find the Android SDK

Confirm both of these:

```bash
flutter config --list | grep android-sdk
cat android/local.properties
```

The SDK path in `local.properties` must exist, and `flutter config` must point at the same directory.

### Release builds

The generated Flutter project signs release builds with the debug key by default. Configure your own signing key before distributing a release APK.
